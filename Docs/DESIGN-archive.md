# RimBob — Archived Design Decisions

Superseded or fully-retired rows moved verbatim out of the [`DESIGN.md`](DESIGN.md) decision log to keep the always-loaded log short. Nothing here is current truth; each row's third column names the superseding decision (still in `DESIGN.md`) or the docs that own the current behavior. History is preserved — rows are moved, never rewritten.

| Decision | Rationale | Archived because |
|---|---|---|
| Mayor Agenda current/history are durable Host runtime state | Browser-side agenda caching is rejected as a confusing source of truth. `AgendaStore` persists the current Agenda and bounded history under the stable machine-local data root and loads it on Host startup, so `/api/agenda/latest` and SSE replay can recover the last good agenda after a restart or failed Mayor LLM call. → [`design/agenda.md`](design/agenda.md), [`design/dashboard.md`](design/dashboard.md) | Superseded by "Unified minister output persistence replaces Agenda-specific durability". |
| Missing Mayor Agenda initializes from a labeled server bootstrap | A new runtime can legitimately have no persisted Agenda, and provider quota failures can prevent the Mayor from creating the first one. Host now creates a conservative, clearly labeled bootstrap Agenda before serving the dashboard when no stored Agenda exists; the Mayor uses the same path if the LLM fails twice before any Agenda exists. This keeps the dashboard useful without pretending the bootstrap is a full LLM agenda. → [`design/agenda.md`](design/agenda.md), [`design/dashboard.md`](design/dashboard.md) | Superseded by "Host rebuilds do not trigger cabinet regeneration" (bootstrap only when no persisted minister output exists at all). |
| Mayor wakes on Host startup, not only on day rollover | Original M1 deferred firing the Mayor until the first in-game day rolled over so we'd never publish a "fake" agenda from cold state. In practice that left the dashboard blank for 24 in-game minutes per session — the player can't tell whether the system is alive. `DayTickOrchestrator` now fires Mayor on the first successful poll (after a full `IngestionDispatcher.RefreshAllAsync`), so the dashboard is useful within ~15s of Host start. The same orchestrator drives subsequent rollovers. | Superseded by "Host rebuilds do not trigger cabinet regeneration" (startup reloads persisted snapshots; orchestrator waits for rollover or manual trigger). |
| Original demand-trigger retired | `POST /api/agenda/refresh` was the first dashboard route for asking the Mayor to run *now*. Dashboard v2 replaced it with `POST /api/cabinet/trigger`, which runs the current live cabinet evaluation path. The old agenda refresh route no longer exists. | Completed route migration; current trigger routes live in [`design/dashboard.md`](design/dashboard.md). |
| Agriculture renamed Food; cabinet domains are production chains or crisp subsystems | "Agriculture" was too narrow for the actual owner of food security. Chef owns harvesting, farming, hunting, cooking, food stockpiles, freezer integrity, and food-chain resource requests. More broadly, each minister should own a production chain or clearly bounded subsystem; every game action should eventually have one primary owner. Clear-cut action ownership is mapped first, with hard cases left explicit. See [`design/ministers.md`](design/ministers.md) and [`design/ministers/food.md`](design/ministers/food.md). | Completed rename; the domain principle lives on in the Cabinet boundary rule section and "Hybrid cabinet accepted". |
| Chef rules emit independent rule advice | Chef deterministic rules no longer use a first-match cascade. A normal rules cycle emits every matched food rule as its own `AdviceItem` and `AgentFlag`; LLM escalation is considered only when no deterministic rule emitted advice. The first slice intentionally has no cap, dedup, or flag consolidation, so multiple Willie follow-up runs per Food cycle are an accepted cost until a later dedup slice proves necessary. See [`design/ministers/food.md`](design/ministers/food.md). | Superseded by "All-hits is the only rules evaluation policy" (adds priority sort/cap and same-`trace` dedup the first slice deferred). |
| Advice and flags use one priority enum | `AdviceItem` and `AgentFlag` use `priority: low | medium | high | critical` instead of separate urgency aliases or fake 1-10 score fields. The single enum drives advice sorting, dashboard display, inter-minister routing, tactical alert behavior, and future arbitration. This is a wire/persistence schema change: no compat code; wipe-and-regen on upgrade. See [`design/advice.md`](design/advice.md). | Refined and fully restated by "Advice and flags share one `Priority` enum and wire field". |
| Active feeder advice dedupes by stable issue id | Until the decision log grows a full supersession/history view, feeder rules should use stable ids for the same unresolved issue so dashboard refreshes replace the active card instead of stacking duplicates. See [`design/advice.md`](design/advice.md). | Superseded by "Active feeder advice is replaced by minister snapshots" (replacement mechanism) and "Concern identity is one typed `RuleId`" (id mechanism). |
| Chef persists replay corpus records | Chef writes append-only records under the configured logs root's `replay/food-YYYYMMDD.jsonl` for rule, LLM, and LLM-failure paths. Records preserve the briefing/context, wake trigger, flags, RAG citations, emitted advice/flags, and LLM raw-output metadata needed for future before/after benchmarking. See [`design/architecture.md`](design/architecture.md) and [`design/evaluation.md`](design/evaluation.md). | Generalized by "Every minister LLM attempt is replayable"; exact file paths are code-owned per "Design docs should not mirror code". |
| Agenda routes retired in favor of minister snapshot routes | `/api/agenda/latest`, `/api/agenda/history`, and `/api/agenda/manual` are removed with no aliases. Dashboard clients use `/api/ministers/{minister}/snapshot`, manual Mayor fallback uses `/api/ministers/mayor/snapshot/manual`, and status/system payloads report `mayor_snapshot_version` plus minister-output metadata instead of `agenda_version` / agenda-store metadata. See [`design/RimAPI.md`](design/RimAPI.md) and [`design/dashboard.md`](design/dashboard.md). | Completed route migration; current routes live in [`design/RimAPI.md`](design/RimAPI.md) and [`design/dashboard.md`](design/dashboard.md). |
